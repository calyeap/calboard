## 3. Structural changes

**Tables: 45 → 29.** Removed from any V1 migration: `theses`, `thesis_assumptions`, `assumption_observations`, `assumption_reviews`, `decisions`, `decision_transaction_links`, `decision_reviews`, `journal_notes`, `predictions`, `fundamental_facts`, `metric_source_policy`, `fact_cross_checks`, `derived_metrics`, `valuation_input_confirmations`, `valuation_runs`, `scenarios`, `etf_holdings`, `embedding_models`, `document_embeddings`, `fx_fixings`, `transaction_groups`, `transaction_legs`.

**Not as stubs.** *"Design the attachment points now. Build the future features later."* The attachment points are stable surrogate IDs, not empty tables.

**Components removed:** `GatedAIPanel`, `FxAgeBadge`, `ThesisEditor`, `AssumptionCard`, `ThesisDiff`, `ReviewPrompt`, `VerdictControl`, `DecisionForm`, `DecisionTimeline`, `JournalNote`, `LookThroughPanel`.

**Jobs removed:** `fx_daily`, `fundamentals_refresh`, `fact_cross_check`, `derived_metrics`, `assumption_rule_check`, `review_scheduler`, `etf_holdings`. **Added:** `fx_spot_refresh` (the only job in the system with no failure escalation, deliberately), `corporate_actions_poll`, `split_guard`, `catalyst_join`.

**Tests removed:** FX calendar fixtures (weekends, holidays, DST) — no historical FX exists to test. **Tests added:** SGD failure injection, split-corruption detection, sort-parameter rejection, and a set of **absence tests** asserting that V2/V3 concepts do not exist in schema, code paths or prompt templates.

**Cost:** ~USD 75–225/month → **~USD 65–175/month**, principally because the fundamentals data tier moves to V2.

## 4.4 Final implementation-readiness corrections

Six corrections applied to the approved v1.2 specification after independent review. **None alters product scope, architecture, roadmap or release structure.** Every item is a schema-validity, migration-ordering or complexity-reduction fix. No new product version was created; the v1.2 files were patched in place.

| # | Issue | Correction | Files |
|---|---|---|---|
| 1 | `watchlist_items.materiality_threshold DEFAULT 'high'` violated its own `CHECK (… IN ('notable','important'))` — the table could not accept a defaults-only insert | Default changed to `'important'`. The rule that watched assets carry a **higher** bar than holdings is preserved and unchanged | TDD §5 |
| 2 | `material_moves.linked_event_id REFERENCES events(id)` was created in M2, but `events` does not exist until M3 — M2 could not migrate | `material_moves` is created in M2 **without** the column, with `catalyst_status` now defaulting to `'pending'`. M3 adds `linked_event_id` as a **nullable column via `ALTER`** once `events` exists. Architecture unchanged: **M2 detects moves; M3 explains them where evidence exists** | TDD §1.1, §6; Build Plan M2, M3 |
| 3 | `document_filters.ai_run_id REFERENCES ai_runs(id)` was created in M3, but `ai_runs` does not exist until M4 — M3 could not migrate | `document_filters` is created in M3 **without** the column and is fully functional for deterministic filtering. M4 adds `ai_run_id` as a **nullable column via `ALTER`**. Rows written in M3 correctly retain `NULL`. Architecture unchanged: **M3 is deterministic; M4 layers AI on top** | TDD §1.1, §7; Build Plan M3, M4 |
| 4 | Cost basis was specified as configurable between average cost and FIFO. FIFO is not a toggle — it requires lot-level accounting that propagates into partial sales, lot selection, transfers carrying lot identity, spin-off basis allocation, corporate-action adjustment of open lots, and per-lot reconciliation | **Average cost only in V1.** No lot table, no lot selection, no configuration switch. The UI states plainly that this is a portfolio-tracking record, **not tax-lot accounting**. Deferring is safe because the append-only ledger allows lots to be reconstructed later if genuinely needed | PRD L8; TDD §4.6, §12; Build Plan M1 |
| 5 | The TDD asserted `event_key` is never NULL, but the column was not declared `NOT NULL`, and no derivation was specified for events with no authoritative external key | `event_key TEXT NOT NULL UNIQUE`, with a **four-tier deterministic derivation** (SEC accession → stable vendor id → `asset:type:period` → `asset:type:date:hash(title_norm)`). No LLM at any tier. Every tier carries a period or date component, so the **zero-tolerance rule against cross-period merging is now structural rather than conventional**. Keys are immutable; **AI may write `significance` only, never `event_type` or `event_key`** | TDD §7.0, §7.1, §12 |
| 6 | `assets.sector_source_id REFERENCES sources(id)` but `sources` was declared after `assets` | `sources` is created first. A full FK-order audit was run across the V1 schema; this was the only ordering defect besides items 2 and 3. **No data model was changed to solve creation order.** A per-milestone migration order is now specified explicitly | TDD §1.1, §2; Build Plan M1 |

**Two additional defects surfaced by the audit and fixed under item 6's remit** (both are documented-invariant gaps, not scope changes):

- **`documents.external_id` was nullable** while `UNIQUE (source_id, external_id)` was relied on for ingestion idempotence. In Postgres NULLs do not conflict, so any news item lacking a vendor ID could be inserted without limit. Now `NOT NULL`, with a deterministic fallback ladder (`vendor_id → url_hash → sha256(title_norm ‖ published_at)`).
- **`documents.body_text` is documented as required for claim validation but must remain nullable**, because `headline_only`, `paywalled` and `failed` retrievals legitimately have no text. The real invariant — *full retrieval implies text* — is now expressed as a `CHECK` constraint, which makes the rule that text-less documents cannot carry sourced claims enforceable rather than aspirational.

**Unchanged by these corrections:** every item in the approved-decisions list — product version boundaries, USD-only accounting, SGD as render-time convenience, no historical or execution FX, multi-account grain, single-table transactions with nullable `link_id`, derived USD cash, EOD-only prices, lightweight watchlist, SEC filings as documents with XBRL in V2, deterministic dedup with semantic clustering deferred, material moves with no invented causality, AI as monitoring assistant with no thesis or decision gating, claim provenance, the unsourced numeric-output guardrail, and the full technology stack.

## 5. V1.2 Architecture Decision Summary

**Frontend.** Next.js App Router with TypeScript; server components for provenance-heavy pages; mobile-first for read paths.

**Backend.** Same TypeScript codebase, modular monolith deployed as two services sharing one database: **web** (UI + API) and **worker** (scheduler + jobs). V1 modules: ledger, marketdata, fxdisplay, documents, events, moves, ai, provenance, ops. V2 attaches fundamentals, thesis, decisions; V3 attaches valuation.

**Database.** PostgreSQL. `NUMERIC(28,10)` for all money and quantity. 23 tables. **No pgvector.**

**Hosting.** Managed platform + managed Postgres — **Render, Singapore region**: one web service, one background worker, one managed Postgres, native cron. ~USD 25–60/month. Portable by construction; self-hosting later is a redeployment, not a rewrite.

**Market data.** One commercial vendor behind an adapter, selected in M0. **EOD prices only, deliberately.** Splits and dividends from the same vendor, with a split-corruption guard because it is the only cross-check V1 has.

**Fundamentals strategy.** **None in V1.** SEC XBRL, financial facts, source policies and derived metrics are V2, preceded by a proper fundamentals-quality de-risking spike.

**FX strategy.** **USD is the sole accounting currency.** SGD is a render-time approximate display fed by one cached spot rate with a source and timestamp — never persisted, never in a calculation, and its failure mode is a string rather than an error.

**News strategy.** SEC filings **as documents** first (free, structured, natural event keys, 8-K item codes), then issuer feeds, then one commercial news provider. Rule-first entity linking over a bounded universe. **Deterministic dedup only.** Full coverage disclosure and an always-inspectable filtered tray.

**AI strategy.** Hosted LLM behind a swappable adapter; cheap model for triage, capable model for summarisation. **News assistant, not investment analyst** — no thesis, valuation, recommendation or causality claims. Monitoring-oriented significance rubric defaulting to `routine`. Unsourced numeric-output guardrail with a narrowly-stated guarantee. Claim provenance with verbatim-excerpt substring validation. `model_id` + `prompt_version` + `input_hash` on every run; caching; hard spend cap with **triage degrading last**. Position quantities and cost basis excluded from prompts by an enforced allow-list.

**Authentication.** WebAuthn passkey primary, TOTP fallback, **no public signup route**. Short-lived httpOnly SameSite=Strict sessions. Strict CSP with no third-party origins on portfolio routes.

**Scheduled jobs.** Database-backed queue in Postgres (`SELECT … FOR UPDATE SKIP LOCKED`) in the worker service. No Redis. Schedules from an exchange calendar in UTC. Every run writes to `job_runs` with a coverage summary. Daily digest email. **`fx_spot_refresh` is the single job permitted to fail silently.**

**Backup.** Platform-managed backups with PITR **plus** an independent encrypted nightly `pg_dump` to a different provider. **Restore executed and verified before launch and quarterly thereafter.**

## 7. Plain-English summary

> **V1 tells me what I own and what is happening.**
>
> **V2 tells me whether what happened matters to my investment thesis.**
>
> **V3 tells me whether the investment is attractive at today's price.**
>
> **V4 helps the system and me learn and automate over time.**

And the implementation principle that governs V1:

> **USD is the source of truth in V1. SGD is only a convenience display.**
